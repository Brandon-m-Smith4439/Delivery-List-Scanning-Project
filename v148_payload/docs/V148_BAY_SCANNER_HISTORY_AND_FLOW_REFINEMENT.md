# v148 Bay Scanner History and Flow Refinement

## Purpose

v148 closes the remaining Bay Scanner layout and history issues found during floor review. It preserves the existing scanner control IDs and API workflow while tightening normal-flow placement, Route Pulse presentation, and physical bay movement history.

## Toolbar and sticky behavior

The Bay Map action toolbar remains in ordinary document flow. The right rail is now a top-aligned flex column, so the scanner begins directly beneath the buttons instead of being distributed lower in the rail. Only `bay-scanner-sticky-slot-v148` becomes sticky after the scanner reaches the top of the viewport.

## Header and Route Pulse

The hidden `bayScanOutStatus` node remains for existing JavaScript compatibility, but the visible `Just now` / waiting badge has been removed. Remove mode hides the two percentage labels beneath Route Pulse because the quantity cards already provide the essential status. Add mode retains the percentages.

## Recent Bay Scans

Recent Bay Scans is no longer a disclosure. It remains open and shows at most two compact, one-line rows with:

- Order Nr.
- Job Nr.
- Action
- Current Bay

Current Bay uses the maintained location-change selector, so authorized users can move the item without opening All Scans. The table uses a fixed layout and does not scroll horizontally or vertically.

## History ownership

Bay Scan history now represents physical item movements only. `get_bay_events()` excludes rows without a line item and returns the Job Nr. used by the compact table. Structural events generated by layout updates, bay creation, and bay deletion are no longer inserted into `bay_events`; older structural rows are filtered from Recent Bay Scans and All Scans.

Administrative `audit_events` records are unchanged, so layout changes remain accountable without flooding operator scan history.

## Preserved behavior

- Add and Remove scanning
- Barcode submission through Enter/scanner input
- Undo and Redo
- Manual Order / Item / Submit
- Route Pulse and in-transit manifest
- Latest activity and All Scans
- Current Bay location correction
- Permissions and existing API routes
- SQLite and future Azure SQL compatibility

No database schema migration is required. No PNG previews are generated or packaged.
